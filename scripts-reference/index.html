Scripts Reference

Every script under scripts/. For the idp CLI, see CLI Reference.

Prerequisites​

PathRequired tools
Local (Kind)git, docker, kind ≥ 0.27, kubectl, helm ≥ 3.14
AWSThe above, plus a configured aws CLI, terraform ≥ 1.5, jq
Auto-installed if missinggo ≥ 1.26 (for the idp CLI), Node.js 24 (for Backstage)

Each script runs a preflight check before doing anything destructive. Walkthroughs: Local Setup, Pre-Deployment Checklist.

setup.sh vs bootstrap-local.sh​

  • setup.sh runs once. It replaces the template placeholders with your values, creates the .env files, builds the idp CLI, then asks local / aws / skip and calls the right bootstrap script.
  • bootstrap-local.sh installs the platform on Kind or Rancher Desktop. It's what you use for day-2 work (--destroy, --start-backstage, recreating the cluster).

On a fresh clone, run setup.sh and nothing else. Running both back to back just repeats a 15–20 minute install. Personalisation has to come first, or ArgoCD, the catalog and ingress hostnames point at unresolved placeholders.

Re-running the bootstrap scripts — caching and parallelism​

All three bootstrap scripts are safe to re-run. They skip work that is provably unchanged and run independent work in parallel:

  • Helm releases are skipped when the chart, version, --set values and values file contents are unchanged and the release is deployed.
  • Image builds are skipped when the source hash is unchanged and the tag still exists in the registry or ECR. Builds run in the background while the rest installs.
  • Fingerprints live in .idp-cache/, but every skip is also checked against live cluster state, so deleting it only costs time.
VariableDefaultEffect
IDP_FORCE01 disables every skip
IDP_BUILD_JOBSncpu/3 (1–4)Concurrent MCP image builds in bootstrap-ai.sh
IDP_HELM_REPO_TTL3600Seconds before chart repo indexes are refreshed
IDP_TIMING1Per-step timings and a slowest-first summary, printed even on failure
HELM_WAIT_SHORT / _MED / _LONG / _XL5m / 10m / 15m / 25mhelm --wait budgets. On a slow link, raise these — a chart still pulling images hasn't failed

On Apple Silicon, AWS images are built for linux/amd64 under emulation, so the Backstage image is the slowest step of a cold AWS bootstrap. docker buildx keeps a layer cache in ECR, so rebuilds only redo changed stages.

Execution flow​

Per new service or test suite (day-2):

idp scaffold service --name my-svc --type nodejs            # via Backstage when running
idp scaffold service --name my-svc --type nodejs --local    # offline
idp scaffold test-suite --name my-e2e --type playwright --service my-svc
scripts/setup-runner.sh --repo my-svc
