Troubleshooting

Issues you may hit on a first install, and how to fix them. setup.sh must finish before bootstrap-local.sh runs. Most surprising failures (empty catalog, no ArgoCD apps, OAuth loops) trace back to skipping it.

Quick diagnosis​

docker info > /dev/null && echo "Docker OK"                       # Docker running?
kind get clusters                                                 # cluster exists?
kubectl get pods -A --no-headers | grep -vE "Running|Completed"   # unhealthy pods
docker ps --filter "name=backstage" --format "{{.Names}} {{.Status}}"
grep -r "moatazeldebsy" backstage/catalog/ local/argocd/ && echo "PLACEHOLDERS NOT REPLACED"

Local bootstrap (bootstrap-local.sh)​

SymptomFix
kind create cluster failsStart Docker; free port 80 (lsof -i :80); delete a stale cluster (kind delete cluster --name idp-mvp); on Rancher Desktop disable Traefik
nginx ingress pending, *.idp.local unreachablePort 80/443 is taken. The preflight only checks on a fresh install, so on an existing cluster check lsof -i :80 -sTCP:LISTEN and kubectl get pods -n ingress-nginx
Many *.idp.local URLs return 503/504 at onceThe Docker host is oversubscribed and the API server is timing out (look for context deadline exceeded to 10.96.0.1:443). Give Docker more CPU/RAM (12 CPU / 24 GB is comfortable) or run less, then re-run the bootstrap
/etc/hosts entries missingsudo sh -c "cat local/hosts-append.txt >> /etc/hosts", then flush DNS (sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder)
Kind node NotReady / URLs dead after a Docker restartRun ./scripts/recover-docker-restart.sh. Details: Kind Node IP Mismatch
kube-proxy crash-loops with "too many open files" (Linux)sudo sysctl -w fs.inotify.max_user_instances=1024 fs.inotify.max_user_watches=655360, persist in /etc/sysctl.conf, delete the kube-proxy pod
ImagePullBackOff after scaffoldingThe image isn't in the local registry. See ImagePullBackOff

Backstage​

Catalog is empty​

docker exec backstage-postgres-1 psql -U backstage backstage_plugin_catalog \
  -c "SELECT count(*) FROM refresh_state;" -c "SELECT count(*) FROM final_entities;"
  • refresh_state > 0 but final_entities = 0: the scaffolder plugin crashed at startup and stopped the refresh loop. Pull the latest code and rebuild (docker compose -f local/backstage/docker-compose.yml build backstage && … up -d).
  • Otherwise wait 60–90 s for migrations, and check GITHUB_TOKEN is set in local/.env.

GitHub OAuth login fails or loops​

  1. The OAuth app callback must be exactly http://backstage.idp.local/api/auth/github/handler/frame (on AWS, the real Backstage hostname printed by bootstrap.sh).
  2. Open http://backstage.idp.local, never localhost:3000. The sign-in popup posts back to the opener's origin, which must match app.baseUrl.
  3. local/backstage/.env needs AUTH_GITHUB_CLIENT_ID and AUTH_GITHUB_CLIENT_SECRET.
  4. Restart with ./scripts/bootstrap-local.sh --start-backstage. docker compose restart does not re-read .env.

Always run ./scripts/verify-secrets.sh first.

Team infrastructure​

Crossplane claim rejected — "owner is required"​

Kyverno's crossplane-require-cost-tags policy requires spec.parameters.owner and spec.parameters.costCenter on every claim. Add them; during a migration you can set the policy to validationFailureAction: Audit temporarily.

idp:team tag missing on a Crossplane resource​

Mutation only runs in team-* namespaces and only on claims created after Kyverno was installed. Check kubectl get policyreport -n <namespace>; recreate older claims.

ExternalSecret: "SecretStore not found: team--secrets"​

The team was scaffolded without an IAM role ARN, so no SecretStore was created. Create the role (terraform apply -var='team_eso_roles=[{name="<name>",cost_center="CC-1234"}]', then terraform output team_eso_role_arns) and re-run the Provision Team Namespace template with the ARN.

Templates from all-templates.yaml not loading (AWS)​

The file must be on main and readable through the GitHub integration. Check kubectl logs -n backstage deploy/backstage | grep -i "all-templates\|location.*error".
